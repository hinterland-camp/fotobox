## Codebase Patterns
- Root monorepo uses Turborepo with pnpm workspaces (apps/* and packages/*)
- Vitest 4 uses `defineConfig` with `test.projects` instead of deprecated `defineWorkspace`
- OxLint configured at root with oxlint.json
- TypeScript base config at root tsconfig.json (ES2022, bundler module resolution)
- pnpm 10 requires `pnpm.onlyBuiltDependencies` in package.json for native deps (esbuild, @parcel/watcher)
- Nuxt 4 uses `app/` directory structure by default (app.vue lives in app/app.vue)
- Tailwind CSS v4 uses `@tailwindcss/vite` plugin directly instead of `@nuxtjs/tailwindcss` module
- Nuxt 4 `tsconfig.json` in workspace just extends `.nuxt/tsconfig.json`
- Check `~/.nuxtrc` for stale global module references that break builds
- electron-vite 5.0 with `electron.vite.config.ts` for Electron + Vue 3 apps (three-process: main, preload, renderer)
- Electron desktop app uses `@electron-toolkit/utils`, `@electron-toolkit/preload`, and `@electron-toolkit/tsconfig`
- Desktop typecheck: `tsc` for node (main/preload) + `vue-tsc` for web (renderer), combined via `pnpm run typecheck:node && pnpm run typecheck:web`
- Root `pnpm.overrides` with `"@types/node": "^22"` needed to avoid dual vite type resolution (node 22 vs 24)
- Shared types package at `packages/shared` uses `workspace:*` protocol for inter-workspace deps
- Shared package uses `tsc` build with `exports` field pointing to `dist/index.js` and `dist/index.d.ts`
- Kiosk mode: `globalShortcut.register` blocks Alt+F4/Cmd+Q/Cmd+W; `allowQuit` flag gates `before-quit` and window `close` events
- Kiosk mode uses `setAllowQuit(true)` export from main/index.ts to allow programmatic exit (used by password-protected exit)
- Settings stored in `app.getPath('userData')/settings.json` — `loadSettings()` creates default file on first access
- IPC pattern: `ipcMain.handle('namespace:method')` in main, `ipcRenderer.invoke()` in preload, typed `window.api` in renderer
- Preload API types declared in `src/preload/index.d.ts` and exposed via `contextBridge.exposeInMainWorld('api', api)`
- Kiosk exit/enter: `win.setKiosk(false); win.setFullScreen(false); win.setAlwaysOnTop(false)` to exit; reverse to re-enter
- Settings IPC: `settings:getAll` returns full Settings object, `settings:get(key)` returns single value, `settings:set(key, value)` updates and persists
- Settings defaults: password='admin', countdownSeconds=3, savePath=~/Pictures/Fotobox/, autoReturnSeconds=30, empty strings for device/path/url fields
- Electron `PrinterInfo` has `name`, `displayName`, `description`, `options` — NOT `isDefault`
- Electron file input `<input type="file">` gives `file.path` (absolute path) in Electron renderer — use this for saving frame paths
- SettingsPanel uses `@change` (not `@input`) to save settings on blur/select, avoiding excessive IPC calls
- CameraPreview component exposes `videoRef` and `stream` via `defineExpose` for capture (US-012) and compositing (US-013)
- Frame overlay: simple `<img>` with `absolute inset-0 pointer-events-none object-cover` over camera preview; `v-if` on framePath to hide when unconfigured
- Prefer `settings:getAll` over multiple `settings:get` calls when loading multiple settings at once
- CountdownOverlay component uses `<Teleport to="body">` with `:key` trick to retrigger CSS animations on each tick
- App.vue `handleCountdownComplete()` is the hook point for triggering photo capture (US-012)
